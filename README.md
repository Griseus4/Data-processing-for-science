# Data processing for science

Python-программа для пакетной обработки экспериментальных электрических характеристик нанообразца. Читает восемь файлов измерений `.dat`, вычисляет показатели по диапазонам напряжения и восьми токовых каналов и сохраняет две матрицы 8 × 8 с метаданными в Excel.

## Задача и результат

Измерительная программа выгружает отдельные текстовые файлы с длинным служебным заголовком. Для сопоставления каналов нужны сводные таблицы. Скрипт автоматизирует чтение файлов, агрегацию измерений, перевод единиц и сборку отчёта. Метаданные пользователь вводит через командную строку.

В репозитории доступны исходные измерения и исторический Excel-результат. Это пример обработки реальных лабораторных данных: разбор приборного формата, операции с таблицами в pandas, расчёт производных величин и экспорт в XLSX. Замеры ускорения работы и оценка точности измерений в материалах проекта отсутствуют.

## Установка

Проверено на Python 3.12.14 с pandas 2.2.3, NumPy 2.3.5 и openpyxl 3.1.5. Это проверенное окружение, а не установленные минимальные версии.

- **pandas** читает `.dat`, вычисляет агрегаты и формирует таблицы.
- **NumPy** импортируется в скрипте, хотя отдельных вызовов NumPy в текущем коде нет.
- **openpyxl** обеспечивает запись `.xlsx` через pandas. Если установлен XlsxWriter, pandas может выбрать его автоматически; отдельно устанавливать его для запуска не требуется.
- `os`, `glob`, `datetime`, `time` и `sys` входят в стандартную библиотеку Python.

Скачайте репозиторий через **Code → Download ZIP** и распакуйте либо клонируйте его:

```bash
git clone https://github.com/Griseus4/Data-processing-for-science.git
cd Data-processing-for-science
python -m venv .venv
```

Активируйте окружение командой для своей оболочки:

| Оболочка | Команда |
| --- | --- |
| Linux / macOS, bash / zsh | `source .venv/bin/activate` |
| Windows, cmd | `.venv\Scripts\activate.bat` |
| Windows, PowerShell | `.\.venv\Scripts\Activate.ps1` |

Затем установите зависимости:

```bash
python -m pip install -r requirements.txt
```

Если системный интерпретатор вызывается как `python3` или `py -3`, используйте это имя при создании окружения. Далее команды приведены для активированного окружения.

## Запуск на примерах

Из корня репозитория:

```bash
python prog2.py "."
```

Общая форма команды, не зависящая от личных каталогов автора:

```bash
python "путь/к/prog2.py" "путь/к/каталогу/измерений"
```

Аргумент — **каталог**, а не отдельный `.dat`. Пути с пробелами заключайте в кавычки. В каталоге должны находиться ровно восемь нужных `.dat`; вложенные каталоги не просматриваются. Для работы с другой серией создайте отдельный каталог. Исходные измерения скрипт не изменяет.

Программа последовательно запрашивает:

| Поле | Поведение |
| --- | --- |
| Дата | `y` — текущая системная дата; `n` — ручной ввод `ДД.ММ.ГГ` |
| Название образца | Произвольный текст |
| Температура | `y` — `Комнатная`; `n` — фиксированная строка `2.4 К` |
| Общее время травления | Целое неотрицательное число секунд |
| Электроды | `y` — `1,2,3,4,5,6,7,8`; `n` — произвольная строка номеров |

Для демонстрационного запуска можно ввести по порядку:

```text
n
06.12.23
ME_a1_F_rig (demo)
y
0
y
```

Дата и основа имени взяты из заголовков примеров. Комнатная температура и `0` секунд здесь — демонстрационный ввод, а не восстановленные условия эксперимента. Метаданные не извлекаются автоматически и не участвуют в расчётах. Введённый список электродов также не меняет сопоставление каналов и столбцов.

После завершения в каталоге измерений появится файл `ГГММДД_ЧЧММ.xlsx` по времени запуска. Повторный запуск в ту же минуту записывает результат по тому же пути и может перезаписать его.

## Формат входных данных

Скрипт рассчитан на конкретный формат приборной выгрузки:

1. Первые **268 строк** пропускаются при чтении чисел. В примерах строка 268 содержит `Werte:`, строка 269 пустая; числовые данные начинаются со строки 270. pandas пропускает пустые строки.
2. Из **строки 267** извлекается номер столбца результата: `int(x[20:-1])`. В примерах это строка вида `Bemerkung Messung : 1`. Положение текста и числа существенно; имя файла не определяет номер.
3. В каждой непустой строке данных должно быть ровно **9 числовых полей**, разделённых табуляцией. Десятичный разделитель — точка; поддерживается экспоненциальная запись.
4. Полям назначаются имена `U`, `I1`, …, `I8`. В разделе описания столбцов заголовка указаны единицы **V** для напряжения и **A** для токов.
5. Для чтения заголовка и данных используется `latin-1`.

Пример числовой строки из `hom196F8.dat`:

```text
3.0373388E-7	-2.4079105E-8	3.6743747E-8	2.9880077E-8	-4.1853196E-8	1.6333412E-10	4.8094801E-9	-5.0453051E-9	8.2477019E-10
```

| Файл | Номер из строки 267 |
| --- | --- |
| `hom196F8.dat` | 1 |
| `hom196F9.dat` | 2 |
| `hom196FA.dat` | 3 |
| `hom196FB.dat` | 4 |
| `hom196FC.dat` | 5 |
| `hom196FD.dat` | 6 |
| `hom196FE.dat` | 7 |
| `hom196FF.dat` | 8 |

Для новой серии нужны уникальные номера 1–8, числовые значения и ненулевой диапазон напряжения. Эти условия пока не проверяются отдельным валидатором. При числе файлов больше восьми скрипт использует первые восемь из `glob`, порядок которого не гарантирован; при меньшем числе файлов выполнение прервётся.

## Вычисления и их смысл

Для каждого файла и каждого токового канала вычисляются размахи по всем его строкам:

```text
ΔU_V = max(U) − min(U)                 # В
ΔU_mV = ΔU_V × 1000                   # мВ, переменная delta_U
ΔI_A = max(Ij) − min(Ij)               # А
S = ΔI_A / ΔU_mV × 10^9               # нА/мВ, переменная delta_I
R = 1000 / S = ΔU_V / ΔI_A / 1000     # кОм
```

Первый блок Excel подписан `I (нА при 1 мВ)`. Его значение — изменение тока, нормированное на диапазон напряжения 1 мВ. По размерности это проводимость в нА/мВ; это не обязательно измеренный ток в точке `U = 1 мВ`.

Для линейной зависимости тока от напряжения `S` соответствует модулю наклона, а `R` — обратной ему величине. Код использует размахи, поэтому теряет знак наклона. Для нелинейной или немонотонной характеристики эти числа остаются отношениями размахов; программа не вычисляет локальную производную, не подбирает линейную модель и не оценивает погрешность. Назвать каждую ячейку сопротивлением конкретной пары контактов без описания схемы подключения нельзя.

При нулевом размахе тока возникает деление на ноль. Удаление выбросов, обработка пропусков и контроль конечности значений отдельно не реализованы; в предоставленных примерах пропусков и бесконечных значений не обнаружено. Экстремумы чувствительны к выбросам.

## Выходная таблица

Создаётся один лист `Sheet1`, без индекса pandas и служебных заголовков DataFrame:

| Диапазон Excel | Содержимое |
| --- | --- |
| `A1:E1` | Названия полей метаданных |
| `A2:E2` | Введённые пользователем значения |
| Строка 3 | Разделитель |
| `A4:I4` | Подпись первого блока и номера столбцов 1–8 |
| `A5:A12` | Номера токовых каналов 1–8 |
| `B5:I12` | Матрица нормированных изменений тока `S` |
| Строка 13 | Разделитель |
| `A14:I14` | Подпись `R (кОм)` и номера столбцов 1–8 |
| `A15:A22` | Номера токовых каналов 1–8 |
| `B15:I22` | Матрица `R` |

Строка матрицы соответствует каналу `I1`–`I8`, столбец — номеру из строки 267 соответствующего файла. Excel содержит готовые числовые значения, а не формулы: изменение `.dat` требует повторного запуска программы.

## Проверка примеров и небольшие исправления

Проверка выполнена 23.10.2026 по исходной версии [e9b7400](https://github.com/Griseus4/Data-processing-for-science/commit/e9b74007f2978e93a6bf74fecba0ec610f65ea09) и файлам из неё.

- Во всех восьми `.dat` прочитано по 26 строк × 9 столбцов. Номера из заголовков покрывают 1–8 без повторов. Диапазоны напряжения составляют примерно **0.999063–1.000804 мВ**.
- Независимый пересчёт по прежним формулам совпал с **64 из 64** значений первого блока и **64 из 64** значений блока R в опубликованном `240102_2009.xlsx` с относительным допуском `10^-12`. Это подтверждает числовое соответствие файлов, а не физическую корректность метода.
- Метаданные исторического XLSX не описывают достоверно эту серию: там указаны `02.01.24`, `No data, I lied` и электроды `-1`, тогда как заголовки `.dat` содержат дату `06.12.2023` и имя `2023\ME_a1_F_rig`. Эти значения в XLSX введены вручную и в проверку расчётов не входят.

При воспроизведении обнаружены три проблемы. В текущем коде внесены небольшие исправления:

| Проблема исходного кода | Исправление |
| --- | --- |
| Чтение заголовка через `open()` зависело от системной кодировки; в UTF-8 возникал `UnicodeDecodeError` | Явно задано `encoding="latin-1"`, как и при чтении числовой части |
| На pandas 2.2.3 присваивание через `.loc[:, elec_num]` в DataFrame без строк оставляло обе матрицы пустыми, хотя программа завершалась | При создании матриц сразу заданы восемь строк `index=range(8)` и числовой тип |
| Прежняя формула `delta_U / delta_I * 1000` повторно использовала уже учтённый диапазон напряжения | Для кОм используется `1000 / delta_I` |

Исторический XLSX сохранён без изменений. Его первый блок совпадает с новым расчётом; блок R отличается из-за исправленной формулы. Например, для файла с номером 1 и канала I1:

| Величина | Значение |
| --- | --- |
| `S`, нА/мВ | 95.37135045231906 |
| Исторический R | 10.4801892956282 |
| Исправленный R, кОм | 10.485329139802317 |

В этих примерах отличие прежнего R от исправленного меньше 0.094%, поскольку диапазон напряжения близок к 1 мВ. Для других диапазонов ошибка прежней формулы может быть существенно больше.

После исправлений выполнен полный запуск через командную строку на копиях всех восьми примеров. Все **128 числовых ячеек** созданного XLSX сверены с отдельным расчётом через стандартные `csv`, `min` и `max`; максимальное относительное расхождение — менее `5 × 10^-16`. Экспорт также проверен с openpyxl 3.1.5. Проверка подтверждает реализацию приведённых формул на этой серии, но не заменяет проверку схемы измерений, калибровки и физической модели.
